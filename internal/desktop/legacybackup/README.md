# Earlier Electron backup recovery

This package decodes the earlier `aterm-backup` version-1 AES envelope and its
`aterm-library` version-1 payload. It does not read files or change application
state. The active Wails restore adapter continues to use the original React UI.

The outer key uses Electron's scrypt parameters (N=16384, r=8, p=1, 32 bytes)
and the envelope's 16-byte salt. AES-256-GCM authenticates the outer document
with `aterm-backup-v1`. The library password catalog and optional compatible-vault
key use that same key with `aterm-electron-vault-v1`. Nonces and tags must be 12
and 16 bytes. Input is limited to 64 MiB. Decoding errors never fall back to a
second format after a recognized modern-vault authentication failure.

Validation rejects malformed required fields, null scalars, unsupported formats,
invalid connection settings, duplicate IDs/aliases, missing references, cyclic
folder/jump graphs and invalid sort scopes. Library conversion preserves identity
paths, host options, directory relationships, timestamps, sort orders and saved
passwords. The project-wide English UI rule applies to restored preferences.
Any returned `CompatibleKey` belongs to the caller and must be cleared.

The service validates an optional embedded compatible vault with its real modern
codec, builds a private SQLite snapshot through the existing database writer,
then seals a new modern vault. All validation completes before confirmation.
The source backup is unchanged. Hosts and restored desktop preferences commit in
one database transaction; a failed import compensates the encrypted-file change.
The legacy format has no authenticated backup creation time, so it is not assigned
a fabricated source date. Actual restore completion has its own timestamp, which
the existing React integration uses to refresh hosts and settings.

Cloud restore and deletion use `aTerm/sync/vault.enc` under the authorized sync
root. The native cloud-delete dialog defaults to Cancel and keeps local
protected data.

## Evidence

`testdata/electron-aes-v1.enc` was generated by the actual Electron 2.5.0
`LibraryStore` and `backupCodec.ts`; it contains only disposable fixture values.
Its public test password is `legacy-fixture-password`. Tests assert recovered
passwords/options/order/preferences, wrong-password and authenticated malformed
library rejection, cancellation, database failure rollback, restart unlock,
cloud path selection, confirmed deletion and renderer refresh signalling.

Regenerate explicitly with the reference checkout's installed tsx:

```sh
/path/to/aterm/node_modules/.bin/tsx internal/desktop/legacybackup/testdata/generate.mts /path/to/aterm
```

The optional live test also generates a fresh backup containing an embedded modern
vault and its protected key. Production does not depend on Node or Electron:

```sh
ATERM_ELECTRON_REFERENCE_DIR=/path/to/aterm go test ./internal/service -run 'Legacy|ElectronEncryptedBackup'
go test -race ./internal/desktop/legacybackup ./internal/service
```

Native file/confirmation/Keychain/iCloud UI acceptance is still pending. Runtime
compensation and SQLite atomicity do not establish durable recovery after a
process/power failure. Restore installation now serializes within one application service, including key
activation and completion state. Queued operations may cancel without changing
live state, and restore points use exclusive filenames. Cross-process/other-writer
coordination and a durable recovery journal remain open.
